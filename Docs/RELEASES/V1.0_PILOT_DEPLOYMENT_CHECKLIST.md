## During the pilot — change-scope rule (restated from `V1.0_READINESS_REVIEW.md` §7.2, not modified)

- **Permitted**: confirmed-defect fixes only, through the normal Task Plan → Approval → Implementation flow.
- **Not permitted**: new features, scope additions, or speculative hardening beyond what a confirmed defect actually requires. A defect found during the pilot authorizes only the fix it requires — nothing broader.
- All fixes remain subject to the same Approval Boundary (`AI_OPERATING_SYSTEM.md` §8) as any other change — a defect that turns out to require a schema change, public contract change, or security-model change still stops for explicit approval, pilot or not.
