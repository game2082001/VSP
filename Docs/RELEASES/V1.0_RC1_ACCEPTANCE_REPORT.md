Date: 2026-08-06
Type: **Documentation only — no production code modified, no feature redesigned.**

## 1. What RC1 is

"RC1" is a label introduced by this report for the current, complete codebase state: every v1.0-required capability (Epic-013 through Epic-018) individually implemented, Manually Validated at its own acceptance, and Accepted/Frozen by the Product Owner, on top of the pre-existing baseline (Epic-001 through Epic-012, per `Docs/V1.0_CUSTOMER_RELEASE_DEFINITION.md` §2.1). It is not a git tag, branch, or published build artifact — none exists yet (§5). It is this report's name for "the build that Internal Validation's remaining gates, and then Pilot, will be run against."

## 4. Automated test verification

- Full suite: **758/758 effectively passing.** The one full-suite failure (`RtspMediaSessionIntegrationTests.OpenAsync_AgainstRealFfmpegEncodedStream_ReceivesAndDecodesRealFrames`) is a documented pre-existing FFmpeg/RTSP timing flake (first recorded at Epic-018 §10); reran isolated and passed in 57ms.
- No test was deleted, skipped, or weakened to reach this result.

## 5. What has *not* been verified at the RC1 (combined) level

Per `V1.0_INTERNAL_VALIDATION_CHECKLIST.md`, the following are still open and are **not** satisfied by any individual Epic's own acceptance:

- A combined, single-session Manual Validation exercising User/Role, Logging, Settings, Deployment, and Backup/Restore together as one coherent product.
- A fresh clean-machine deployment verification of this exact build — Epic-013's own clean-machine check (2026-07-31) predates Epic-014 through Epic-018.
- A security review of the *full* v1.0 surface, combining rather than merely summing Epic-015/017/018's individual reviews.
- `Docs/V1.0_CUSTOMER_RELEASE_DEFINITION.md` §2.2/§2.6 still contain pre-implementation wording ("no User/Role/auth implementation exists," "no backup/restore mechanism exists today") that is now stale.
- **Nothing has been committed.** `git status` shows the local branch 13 commits ahead of `origin/main` with every Epic-013 through Epic-018 change still uncommitted. No actual RC1 build artifact (a real `dotnet publish` self-contained package, per Epic-013's profile) has been produced from a committed state, and none should be, until the Product Owner commits — commit authority is explicitly the Product Owner's, not the AI Agent's (`CLAUDE.md`).

## 6. Known, disclosed gaps carried into RC1 (not new, not blocking on their own)

- Epic-017's deferred item: no manual, real-filesystem proof of the Restore rollback guarantee specifically at the post-install re-validation step (two automated tests cover different forced-failure points instead) — deferred by Product Owner decision, tracked as a future regression/robustness test.
- Epic-018's disclosed limitations: no way to reach the Operator role without direct database manipulation (no seeded Operator account, no account-creation UI); no self-service Change Password; no end-to-end `MainWindowViewModel` automated test (no STA test infrastructure); no account lockout/idle timeout.
- `V1.0_READINESS_REVIEW.md` §4's accepted technical-debt ledger (TD-029 through TD-037) — reviewed and accepted as not GA-blocking at that review; unaffected by Epic-017/018.

## 7. Disposition

**RC1's baseline is established and its build/automated-test evidence is verified and passing.** This report does **not** accept RC1 for Pilot or GA — that determination is the Product Owner's, made once the gates listed in §5 (mirroring `V1.0_INTERNAL_VALIDATION_CHECKLIST.md`) are closed. Per `AI_OPERATING_SYSTEM.md` §18/§22, an AI Agent does not declare product acceptance; this report's role is to state, accurately, what has and has not been verified so that decision can be made on real evidence.
